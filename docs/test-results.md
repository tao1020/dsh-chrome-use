# 本机验收记录

## 环境与范围

2026-10-28，在 macOS、真实 Google Chrome 和 Harness 0.2.1-rc.3 上测试。测试模型为 OpenCode Go 提供的 `deepseek-v4.1-flash`。通过 Harness 的 headless 命令行启动独立会话，保留工具调用记录和最终报告。

浏览器验收针对扩展 0.1.1，只操作本机专用测试页。Codex 没有同时控制这些页面。首次测试发现后台标签页收不到鼠标事件；增加 `Page.bringToFront` 后重新验收通过。

## 真实浏览器结果

| 项目 | 结果与证据 |
|---|---|
| 页面读取 | 正确读取测试页标题、按钮和输入框；没有返回密码明文 |
| 输入、点击 | 显示“你好，DeepSeek 验收 123”；页面记录 `isTrusted=true` |
| 清空、键盘 | 空文本清空成功；Tab 将焦点移动到问候按钮 |
| 滚动 | `scrollY` 从 0 到 600，再返回 0 |
| 截图 | 保存 PNG，121,014 字节；Codex 检查图像，确认包含问候文字和 `isTrusted=true` |
| 错误采集 | 捕获控制台错误、JavaScript 异常和 HTTP 503；网络 URL 未带测试查询参数 |
| 失败路径 | 禁用按钮报 `ELEMENT_DISABLED`；调试脚本异常报 `JAVASCRIPT_ERROR` |
| 页面导航 | 切换页面后旧元素引用报 `STALE_ELEMENT`；返回首页后仍可操作 |
| 免逐页授权 | `release` 后再次 `claim` 成功，全程无需用户点击授权 |
| 页面限制 | 拒绝 `chrome://settings/`，没有创建内部页面标签 |
| 服务重启 | 另开 Harness 进程后，第一次查询未连接，等待 10 秒后恢复；全程未调用 `chrome_pair` |
| 收尾 | 测试页已释放，最终占用列表为空 |

## 自动化与检查

Node.js 24.21.0 上的 22 项测试通过。覆盖配对令牌持久化、桥接服务重启、扩展 worker 启动重连、手动断开停止重连、会话占用、取消、超时、延迟 attach 清理、页面限制、输入和日志边界。

还检查了 JavaScript 语法、扩展 manifest、包版本一致性和打包文件。源码经过完整差异检查及第二次简化检查。

## 未覆盖范围

浏览器验收之后新增的 worker 启动自动恢复和弹窗配对提示，通过了自动化测试；尚未在重新加载后的真实 Chrome 中单独验收。真实浏览器中的手动“断开连接”按钮及弹窗外观也尚未验收。自动化测试已检查对应断开和重连行为。

这份记录只证明本机专用测试页上的功能。尚未覆盖复杂网站、跨域 iframe、Windows 或 Linux 的真实浏览器，也未完成 Chrome 扩展商店审核。
